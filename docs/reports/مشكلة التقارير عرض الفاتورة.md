# مشكلة التقارير — عرض الفاتورة (فواتير التوصيل)

**التاريخ:** 05-10-2026 · **فحص فقط — بدون أي تعديل على الكود**

**المسار:** `GET /admin/finance/reports/drivers/invoice/delivery`
**زر «عرض الفاتورة»:** `GET /admin/finance/reports/drivers/invoice/delivery/loadPDF/{id}`
**المتحكم:** `Application\Admin\Controllers\Finance\Reports\Driver\InvoiceDeliveryController@show`

---

## الحكم: السبب محدَّد ومُثبت بالتشغيل — وهو **بيئي (خادم)** وليس في كود الصفحة 🔴

خطأان متتاليان يُفشِلان الطلب **قبل إنتاج أي PDF**، وأولهما يقع في السطر 30.

---

## 1) العطل الأول — فشل رمز QR (السطر 30-36) 🔴

```php
$displayQRCode = GenerateQrCode::fromArray([...])->render();   // السطر 30-36
```

**النتيجة المُثبتة:**
```
chillerlan\QRCode\QRCodeException: ext-gd not loaded
```

حزمة `salla/zatca` تولّد رمز QR عبر `chillerlan/qrcode` الذي **يتطلب امتداد PHP `gd`**.

| الفحص | النتيجة |
|---|---|
| `extension_loaded('gd')` | **NO ❌** |
| `salla/zatca` مثبَّت | ✅ نعم |
| `ext-gd` | 🔴 **مفقود** |

⇒ **الطلب يموت هنا** — قبل `\PDF`(No رbefore) stage، فلا يصل إنتاج الملف.

---

## 2) العطل الثاني — محرك PDF غير متوفر (السطر 37) 🔴

```php
$pdf = \PDF::loadView('admin::pages.pdf.finance.reports.driver.invoice.index', ...);
```

**`config/app.php`**
```php
'PDF' => Barryvdh\Snappy\Facades\SnappyPdf::class,
```

⇒ `\PDF` يشير إلى **Snappy**، وهو يحتاج الملف التنفيذي **wkhtmltopdf**.

**النتيجة المُثبتة بتشغيل المحرك فعلياً:**
```
RuntimeException: The exit status code '1' says something went wrong:
stderr: "'wkhtmltopdf.exe' is not recognized as an internal or external command"
command: wkhtmltopdf.exe --lowquality --load-error-handling "ignore" ...
```

| الفحص | النتيجة |
|---|---|
| `wkhtmltopdf` على PATH | 🔴 **غير موجود** |
| `WKHTMLTOPDF_PATH` في `.env` | 🔴 `NULL` |
| `config('snappy.binary')` | `wkhtmltopdf.exe` (افتراضي) |

## 4) 🔴 الأثر أوسع — كل صفحات PDF في المشروع معطّلة

الثلاثة تستخدم **نفس الـ facade `\PDF`**:

| الصفحة | المتحكم / المكوّن |
|---|---|
| **فاتورة التوصيل** (هذه المشكلة) | `InvoiceDeliveryController@show` |

| PDF طلبات الشركة | `App\Application\Admin\Livewire\Company\Tabs\Info\Pdf` |

**إصلاح السطر 37 وحده لن يكفي** — العطل يمتد إلى بقية صفحات PDF.

## 5) ⚠️ خيار Dompdf **غير متاح** للاستخدام الفوري

`barryvdh/laravel-dompdf` **مثبَّت في `composer.json`** لكن:

| الفحص | النتيجة |
|---|---|
| محتويات `vendor/barryvdh/laravel-dompdf/src/` | `PDF.php` + `ServiceProvider.php` فقط |
| `Barryvdh\DomPDF\Facade` | **غير موجود** ❌ |
| `ServiceProvider` مُسجَّل | **NO** ❌ |
| alias في `config/app.php` | غير مُعرَّف |

⇒ **تبديل الـ alias إلى Dompdf ليس حلاً مباشراً**؛ الحزمة ناقصة/معطوبة وتحتاج إصلاحاً أولاً.

## 7) بيانات `merchant_orders` فارغة محلياً

```
merchant_orders total = 0
```
⇒ **لم أستطع اختبار الجدول نفسه** (لا صفوف). الاختبار تم على مسار PDF مباشرة.
لكن `ext-gd` و `wkhtmltopdf` **مفقودان على أي خادم لم يثبّتهما** — وهذا سبب العطل.

## الحل المقترح (لم يُنفَّذ)

### الخيار A — تثبيت المتطلبات على الخادم (الأقل تدخلاً في الكود)
1. تفعيل امتداد **`gd`** في PHP
2. تثبيت **wkhtmltopdf** وضبط `WKHTMLTOPDF_PATH` في `.env`

### الخيار B — التحويل إلى Dompdf
يتطلب أولاً **إصلاح حزمة `laravel-dompdf`** (ناقصة)، ثم تغيير الـ alias.
⚠️ Dompdf لا يحتاج wkhtmltopdf لكنه يحتاج `gd` أيضاً.

### الخيار C — حذف/اختياري رمز QR
تجاوز السطر 30-36 يزيل أول عطل، لكنه **يلغي متطلب ZATCA** — غير مقبول مالياً.

### في كل الأحوال — إصلاحات جانبية مطلوبة
- نقل البائع ورقم الضريبة من الكود إلى جدول البيانات
- حذف الملف الميت `all.blade.php` أو ملؤه
